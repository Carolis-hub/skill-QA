Resumo

Objetivo: Todos os leitores de ConnectionString dos projetos de back-end leem a string com parâmetros adicionais (ex.: Encrypt=True, Connect Timeout=30) e abrem a conexão com todas as opções, para SQL Server e Oracle, sem quebrar as strings antigas (descrição da US).

Fonte técnica: Card Análise #164325 (Done) e PRs #29779 (smartshare-net8), #29780 (SmartShare, Clássico) e #29781 (smartshare-core, Share4). O dev declara que o roteiro de validação manual (SQL Server e Oracle) não foi executado e que a lista de chaves do Calendar OleDb é provisória. Observação: a análise de negócio está Bloqueada (CA 7, CA 8, CA 13 e Premissa 2 remetem ao legado sem definir o resultado), e por isso esses pontos aparecem como hipótese.

Origem (siglas): CA = Critérios de Aceite da US; CT = Casos de Teste do dev (card Análise); PI = Pontos de Impacto do dev (card Análise); hipótese = depende de definição de PO/PM/dev.

Histórico de defeitos considerado: Busca de Bugs no projeto SHARE-4 por termos da US (connection string, parâmetros adicionais, WebConfig, DbConn): nenhum resultado relacionado. Não há cenário de regressão vindo de defeito histórico.

Dimensões cobertas: Positivo, negativo, dados e regressão cobertas. Permissão (#21): N/A, a US só lê a string do arquivo de configuração e não tem perfil de usuário. Concorrência (#26): N/A, a US é só de leitura da string, sem recurso disputado.

Critérios de aceite

  • CA1 — o PBI traz a lista de todos os pontos que leem a string (projeto, local no código, como leem).
  • CA2 — string com Encrypt=True;Connect Timeout=30: conexão aberta com todas as opções valendo.
  • CA3 — string antiga do legado, sem extras: a conexão funciona como antes.
  • CA4 — chaves em qualquer formato (data source, USER ID, Initial Catalog, Server, UID) reconhecidas.
  • CA5 — valores entre aspas com ; ou = lidos por inteiro.
  • CA6 — string terminada em ; lida sem erro.
  • CA7 — string Oracle com parâmetro extra: conexão aberta com o parâmetro, no formato Oracle do legado.
  • CA8 — parâmetro inválido não é ignorado: o provider devolve o erro, tratado como hoje e sem a senha.
  • CA9 — string com extras escrita à mão: todos os projetos leem e conectam.
  • CA10 — todos os leitores da lista do CA 1 testados com extras; nenhum ignora os extras.
  • CA11 — a mesma string lida por projetos diferentes tem o mesmo resultado.
  • CA12 — conexão aberta e liberada como hoje, sem vazar conexões.
  • CA13 — string inválida: erro tratado como hoje, sem derrubar o sistema e sem expor a senha.
  • CA14 — nem a senha nem a string em texto aberto aparecem nos logs.
  • CA15 — instalação existente com string antiga continua conectando sem alterar a configuração.
