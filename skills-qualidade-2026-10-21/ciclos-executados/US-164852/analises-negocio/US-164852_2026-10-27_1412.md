# Análise de Negócio — #164852 Migração tela de gerenciamento | Gerenciamento de índice (BE) | Consumo pela camada ECM

**Projeto:** SHARE-4 | **Tipo:** Product Backlog Item | **Status:** Approved

## Objetivo da alteração
Garantir que a camada ECM continue oferecendo apenas tipos de índice ativos, com as opções na ordem correta, para que a configuração feita pelo administrador no Share 4 se reflita no lançamento, na busca e nos processos com publicação. (descrição: User Story e Contexto)

É a sexta de seis US de BE, originada da divisão da US única de BE do Gerenciamento de índices (Feature 162599); os critérios mantêm a numeração original. Reúne regras que a camada ECM já aplica e "não podem regredir". (descrição: Origem e Contexto)

## Comportamentos esperados (contratos verificáveis)
- Quando a camada ECM carrega uma lista de códigos de tipo para lançamento/busca, o sistema deve devolver só tipos com `st_ativo = 1`, ordenados por `vl_ordenacao`. (CA 73)
- Quando a lista de códigos de tipo é vazia, o sistema deve devolver nulo. (CA 73)
- Quando os valores de um tipo Seleção ou Múltipla Seleção são carregados, o sistema deve devolver só os valores ativos, em ordem alfabética crescente. (CA 74)
- Quando o Tipo de valor é Números, o sistema deve ordenar como texto ("10" antes de "9"), como no Clássico. (CA 74; decisão da PM em 22/10/2026)
- Quando os valores de um tipo com Tipo de valor = Data são carregados, o sistema deve ordenar pelo valor convertido em data. (CA 75)
- Quando um valor não converte em data durante a ordenação, o sistema deve manter a ordem original e gravar erro no log (tipo Erro, aplicação SmartShare 4, código do tipo e do usuário), sem derrubar a requisição. (CA 76)
- Quando, no Início com Publicação, o valor de um índice Seleção/Múltipla Seleção é copiado para campo do formulário do tipo caixa de seleção, marcador ou listbox, o sistema deve gravar o código do valor (`cd_indice`). (CA 77)
- Quando o campo do formulário é de outro tipo, o sistema deve gravar a descrição do valor; em campo de texto ou área de texto, deve concatenar os valores com ", ". (CA 78)
- Transversais (Definição de pronto): requisição sem sessão válida ou sem permissão no menu de Configurações → 401/403 sem executar a operação (CA 95); usuário sem permissão de gerenciar índices não inclui/altera/exclui, mesmo vendo a listagem (CA 96); SQL sempre com parâmetros nomeados, exceto o SQL de consulta cadastrado como regra de negócio (CA 97); comportamento idêntico em SQL Server e Oracle, inclusive chave gerada na inclusão e paginação (CA 98); falha técnica devolve mensagem padronizada ao FE, detalhe no log, sem vazar SQL, stack trace ou string de conexão (CA 99).

## Regras explícitas
- Só tipos ativos (`st_ativo = 1`), ordenados por `vl_ordenacao`; lista vazia → nulo. (CA 73)
- Opções: só ativas, ordem alfabética crescente. (CA 74)
- Números ordenam como texto, decisão da PM (22/10/2026), nada muda para usuários atuais. (CA 74; tabela de decisões)
- Tipo Data ordena pelo valor convertido em data. (CA 75)
- Falha de conversão: mantém ordem original, registra log de erro, não derruba a requisição. (CA 76)
- Início com Publicação: `cd_indice` para caixa de seleção/marcador/listbox; descrição nos demais; concatenação com ", " em texto/área de texto. (CA 77, 78)
- Critérios transversais 95 a 99. (Definição de pronto)

## Regras implícitas
- IMPLÍCITA: a ordenação por `vl_ordenacao` (CA 73) refere-se à ordem dos tipos; a ordem alfabética (CA 74) refere-se às opções. Raciocínio: cada critério trata de objeto distinto.
- IMPLÍCITA: "Múltipla Seleção" em campo de texto/área de texto gera uma única string com valores separados por ", " (CA 78), pois só há concatenação quando há mais de um valor.
- IMPLÍCITA: a lista vazia retornar nulo (e não lista vazia) é contrato a ser verificado literalmente. (CA 73)

## Condições e exceções
- Tipo do índice: Seleção/Múltipla Seleção (CA 74, 77, 78) e Tipo de valor Data (CA 75) ou Números (CA 74).
- Tipo do campo do formulário de destino: caixa de seleção/marcador/listbox × demais × texto/área de texto. (CA 77, 78)
- Valor não conversível em data. (CA 76)
- Sessão inválida, sem permissão no menu de Configurações ou sem permissão de gerenciar índices. (CA 95, 96)
- Banco SQL Server ou Oracle. (CA 98)
- Exceção ao SQL parametrizado: SQL de consulta cadastrado como regra de negócio. (CA 97)

## Informações ausentes
- Informação não encontrada / necessita validação: CA 76 não define o formato da mensagem de erro no log nem o que significa "código do tipo e do usuário" quando não há usuário identificado.
- Informação não encontrada / necessita validação: CA 74 não esclarece se a ordem alfabética diferencia maiúsculas/minúsculas e acentos (apenas "como no Clássico" para Números).
- Informação não encontrada / necessita validação: CA 75 não define a ordem (crescente/decrescente) da ordenação por data.
- Informação não encontrada / necessita validação: CA 77/78 não definem o comportamento para Múltipla Seleção em campo de seleção única (caixa de seleção) nem o separador/estrutura em listbox de múltiplos valores.

## Ambiguidades
- CA 76 "mantém a ordem original": pode significar a ordem de carga do banco ou a ordem alfabética de CA 74. Se só alguns valores não convertem, não está dito se a lista toda mantém a ordem original ou só os inválidos.
- CA 78 "grava a descrição do valor": para Múltipla Seleção em campo que não é texto/área de texto, não está dito como múltiplos valores são gravados.
- CA 73 "devolve nulo" para lista vazia: ambíguo se também vale para lista sem nenhum tipo ativo (o texto só cita lista de códigos vazia).

## Riscos identificados
- Regressão em lançamento, busca e processos se tipos inativos aparecerem ou a ordem mudar.
- Números ordenados como texto ("10" antes de "9") pode ser lido como defeito por quem não conhece a decisão da PM; manter a decisão rastreável.
- Falha na ordenação por data derrubar a requisição ou passar silenciosa sem log.
- Gravar descrição no lugar do código (ou o inverso) no Início com Publicação, corrompendo dados do formulário.
- Divergência de comportamento entre SQL Server e Oracle (CA 98) e vazamento de detalhes técnicos em erros (CA 99).
- Quebra de segurança por concatenação de SQL (CA 97) ou falta de bloqueio por permissão (CA 95, 96).
