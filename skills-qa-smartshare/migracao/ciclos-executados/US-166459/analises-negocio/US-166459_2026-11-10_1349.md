## Objetivo da alteração
Permitir informar, validar, testar e guardar parâmetros adicionais de conexão (ex.: `Encrypt=True`, `Connect Timeout=30`) por cliente no Configurador do Agent, e fazer todo ponto que monta a string de conexão do cliente usá-los, com as mesmas regras da WebConfig (#162683). (descrição: User Story, Objetivo)

## Comportamentos esperados (contratos verificáveis)
- Quando abro a sub-aba "Banco de Dados" de cliente novo, o sistema deve mostrar o bloco "Parâmetros adicionais (opcional)" com contador "00", sem linhas e com botão de criar. (CA 1)
- Quando crio/excluo parâmetro, o sistema deve adicionar/remover a linha Chave/Valor (foco na Chave) e o contador deve acompanhar as linhas preenchidas. (CA 2)
- Quando salvo com linha totalmente vazia, o sistema deve descartá-la sem erro. (CA 3)
- Quando salvo com valor sem chave, o sistema deve exibir "Informe a chave do parâmetro.", abrir a sub-aba com foco na linha e não gravar. (CA 4)
- Quando salvo com chaves repetidas (ignorando maiúsculas e espaços), o sistema deve exibir "Chave duplicada: “X” já foi informada." e não gravar. (CA 5)
- Quando salvo ou testo com chave reservada (`Password`, `PWD`, `Data Source`, `User Id`…), o sistema deve exibir "Use o campo próprio acima.", não gravar nem testar, e não sobrescrever os campos próprios. (CA 6)
- Quando salvo parâmetro comum (`Encrypt=True`), o sistema deve aceitá-lo. (CA 7)
- Quando troco o provider (SQLServer/Oracle), o sistema deve revalidar os parâmetros. (CA 8)
- Quando salvo cliente SQLServer com `Encrypt=True` e `Connect Timeout=30`, o XML deve guardar as duas chaves, na ordem, com valores criptografados, e os demais campos inalterados. (CA 9)
- Quando qualquer ponto do Agent monta a string, ela deve ser `Data Source=…;database=…;user id=…;password=…;Encrypt=True;Connect Timeout=30`. (CA 10)
- Quando serviço, jobs, AD/Azure, viewer padrão, `SmartShare.Ecm.BLL` e `SmartShare.BPM` conectam, todos devem usar os parâmetros. (CA 11)
- Quando o cliente tem XML antigo (sem parâmetros), a string deve ser idêntica à de hoje e a conexão funcionar. (CA 12)
- Quando o valor tem `;` ou `=`, a string deve ser válida e trazer o valor como digitado. (CA 13)
- Quando cliente Oracle tem parâmetro aceito, a string deve seguir o formato Oracle atual (sem `database`) com o parâmetro no fim. (CA 14)
- Quando abro a tela com cliente novo, o Salvar deve estar desabilitado até um Testar com sucesso. (CA 15)
- Quando salvo cliente existente, o teste deve rodar sozinho com os parâmetros; passando, grava e mostra "Cliente alterado com sucesso!"; falhando, mostra erro e não grava. (CA 16)
- Quando testo com sucesso, deve usar os dados da tela incluindo parâmetros, mostrar "Conexão realizada com sucesso." e não gravar. (CA 17)
- Quando o banco não responde, o teste deve terminar no tempo limite. (CA 18)
- Quando o teste falha, deve mostrar "Falha ao conectar. Erro: …" sem a senha e sem gravar. (CA 19)
- Quando há parâmetro desconhecido (`Foo=1`), o erro do driver deve ser exibido; não ignorar em silêncio. (CA 20)
- Quando altero parâmetro após Testar em cliente novo, o Salvar deve voltar a exigir Testar (proposta). (CA 21)
- Quando abro cliente existente, os parâmetros aparecem (contador "01") e a senha vem vazia. (CA 22)
- Quando altero só um parâmetro com senha vazia, a senha salva é mantida. (CA 23)
- Quando salvo `Token=abc123`, o valor não deve aparecer em texto aberto no XML; ao reabrir, volta descriptografado e a conexão usa o valor correto. (CA 24 e 25)
- Clientes sem parâmetros: cadastro, alteração, ativação, inativação e exclusão funcionam como antes, incluindo aviso "Nenhum cliente ativo" e botão Iniciar. (CA 26)

## Regras explícitas
- RN-01 Providers SQLServer e Oracle (`System.Data.SqlClient`, `System.Data.OracleClient`), os mesmos da WebConfig. (descrição)
- RN-02 Lista livre opcional chave/valor; linhas totalmente vazias descartadas. (descrição)
- RN-03 Validação por linha com as mensagens da #162683. (descrição)
- RN-04 Chaves reservadas e apelidos (`Data Source`, `database`, `user id`, `password`, `Server`, `Address`, `Addr`, `Network Address`, `Initial Catalog`, `UID`, `User`, `User Name`, `PWD`). (descrição)
- RN-05 Escape de `;`, `=` e aspas só nos parâmetros novos. (descrição)
- RN-06 Novo campo no XML (`ConfigClienteInfo`), XML antigo = sem parâmetros, sem perda de dados. (descrição)
- RN-07 Todos os pontos de montagem incluem os parâmetros após os campos atuais; sem parâmetros = string idêntica à de hoje. (descrição)
- RN-08 Fluxo de salvar igual ao de hoje (novo: Salvar desabilitado até Testar; existente: teste automático). (descrição)
- RN-09 Abrir cliente carrega tudo menos a senha; senha vazia mantém a salva. (descrição)
- RN-10 Testar usa campos + parâmetros, sem gravar; mensagens atuais mantidas. (descrição)
- RN-11 Valores dos parâmetros criptografados no XML (padrão WebConfig: valor a valor, chave legível); decisão da PM 09/11. (descrição)

## Regras implícitas
- IMPLÍCITA (declarada na US): erros de parâmetro em caixa de mensagem, com seleção da sub-aba e foco no campo (padrão `ValidarCampos`). (RN-03)
- IMPLÍCITA (declarada na US): a lista de chaves reservadas é a mesma nas duas telas. (RN-04)
- IMPLÍCITA (declarada na US): como não se sabe qual parâmetro é sensível, a criptografia vale para todos os valores. (RN-11)
- IMPLÍCITA (declarada na US): ponto de montagem esquecido faz o Agent conectar de formas diferentes no mesmo cliente. (RN-07)
- IMPLÍCITA (minha leitura): a criptografia de valores (RN-11) exige que o Agent descriptografe os valores ao montar a string, senão o driver recebe o valor cifrado; a US já aponta o efeito nos leitores.

## Condições e exceções
- Cliente novo × existente: Salvar desabilitado até Testar × teste automático ao salvar. (RN-08)
- Provider SQLServer × Oracle: Oracle sem `database` na string; parâmetros revalidados na troca. (RN-01, CA 8, 14)
- Senha vazia ao editar cliente existente mantém a salva. (RN-09)
- Cliente sem parâmetros / XML antigo: comportamento e string inalterados. (RN-06, RN-07)
- Chave reservada recusada tanto em Salvar quanto em Testar. (CA 6)
- Tela sem botão Cancelar (não se aplica). (edge cases)

## Ambiguidades
- CA 8 (regras "do novo provider") × RN-04 (lista única de reservadas): pode significar revalidar com a mesma lista, ou lista distinta por provider.
- CA 13 (escape): "valor exatamente como digitado" na string × RN-05 ("escapado"): a string pode conter o valor escapado/entre aspas, que o driver interpreta como o valor original; o CA deve ser lido como valor efetivo.
- CA 11 diz "todos conectam com os parâmetros valendo", mas a tela "Banco de Dados do Agent" e a cópia em `SmartShare.Migracao.Repositorio` estão declaradas fora: a abrangência de "todos" depende dessas decisões.
- CA 10 mostra o valor em texto claro na string montada; RN-11 grava cifrado no XML: a string montada em memória traz o valor já descriptografado.

## Riscos identificados
- Ponto de montagem esquecido (entre ~37 arquivos): Agent conecta sem os parâmetros só nesse ponto.
- Valor cifrado chegando cru ao driver se leitor (Agent ou leitores da WebConfig/#164248) não descriptografar.
- Agent antigo rodando junto com parâmetros gravados: conecta sem eles.
- Ordem de release com #162683/#164248.
- Regressão em clientes com XML antigo se a leitura do novo campo falhar ou a gravação perder dados.
- Escopo fora (BancoDadosAgent, Migracao.Repositorio) pode deixar comportamento divergente entre telas.
- Senha com `;` já quebra a conexão hoje (campos atuais não escapados), pendente de decisão do dev.
