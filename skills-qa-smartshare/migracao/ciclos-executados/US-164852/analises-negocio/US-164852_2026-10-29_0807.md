# Análise de Negócio — #164852 Migração tela de gerenciamento | Gerenciamento de índice (BE) | Consumo pela camada ECM

**Projeto:** SHARE-4 | **Tipo:** Product Backlog Item | **Status:** Committed (coluna Análise) | **Módulo:** ECM | **Pai:** Feature 162599

## Objetivo da alteração
Garantir que a camada ECM continue consumindo os tipos de índice configurados no Share 4 sem regressão: só tipos ativos, ordenados; opções ativas em ordem alfabética; ordenação por data; e regra de Início com Publicação. Reflete no lançamento, na busca e nos processos o que o administrador configura. (descrição: User Story, Contexto)

## Comportamentos esperados (contratos verificáveis)
- Quando a camada ECM carrega uma lista de códigos de tipo para lançamento/busca, o sistema deve devolver só tipos com `st_ativo = 1`, ordenados por `vl_ordenacao`; lista vazia devolve nulo. (CA 73)
- Quando os valores de um tipo Seleção/Múltipla Seleção são carregados, o sistema deve devolver só valores ativos, em ordem alfabética crescente; no Tipo de valor Números a ordem é de texto ("10" antes de "9"). (CA 74; decisão PM 22/10/2026)
- Quando o tipo tem Tipo de valor = Data e os valores são carregados, o sistema deve ordenar pelo valor convertido em data. (CA 75)
- Quando um valor não converte em data durante a ordenação, o sistema deve manter a ordem original e gravar erro no log (tipo Erro, aplicação SmartShare 4, código do tipo e do usuário), sem derrubar a requisição. (CA 76)
- Quando, no Início com Publicação, o índice é Seleção/Múltipla Seleção e o campo do formulário é caixa de seleção, marcador ou listbox, o sistema deve gravar o código do valor (`cd_indice`). (CA 77)
- Quando o índice é Seleção/Múltipla Seleção e o campo é de outro tipo, o sistema deve gravar a descrição do valor; em campo de texto ou área de texto, concatena os valores com ", ". (CA 78)
- Requisição sem sessão válida ou sem permissão no menu de Configurações deve retornar 401/403 sem executar a operação. (CA 95)
- Usuário sem permissão de gerenciar índices deve ser bloqueado ao incluir/alterar/excluir, mesmo vendo a listagem. (CA 96)
- SQL deve usar sempre parâmetros nomeados, exceto o SQL de consulta cadastrado como regra de negócio. (CA 97)
- Comportamento idêntico em SQL Server e Oracle, inclusive chave gerada e paginação. (CA 98)
- Falha técnica deve devolver mensagem padronizada ao FE, registrar detalhe no log e não vazar SQL, stack trace ou string de conexão. (CA 99)

## Regras explícitas
- Só tipos ativos, ordenados por `vl_ordenacao`; lista vazia → nulo (CA 73).
- Só valores ativos; ordem alfabética crescente; Números ordenados como texto, decisão da PM em 22/10/2026 (CA 74, tabela de decisões).
- Falha de conversão de data não derruba a requisição e é logada (CA 76).
- Regras de gravação no Início com Publicação por tipo de campo (CA 77, 78).
- Definição de pronto transversal: CA 95 a 99.
- Fora da entrega: cadastro/alteração dos tipos (BE 02 a BE 04) e manutenção das opções (BE 05). (descrição, Escopo)

## Regras implícitas
- IMPLÍCITA: em CA 75, a conversão de data depende do formato gravado pela BE 05; o comentário do mapa assume dd/MM/yyyy (D-02), mas a US não informa o formato. Ver Informações ausentes.
- IMPLÍCITA: em CA 76, a lista inteira mantém a ordem original quando há um valor inválido ("mantém a ordem original"), e não só o valor inválido. É a leitura literal do CA, mas o comportamento com valores válidos ao redor não está detalhado.
- IMPLÍCITA: "só ativos" vale também para valores/opções por consequência de CA 73/74 (tipos inativos e valores inativos não aparecem na camada ECM).

## Condições e exceções
- Lista de códigos de tipo vazia → nulo (CA 73).
- Tipo de valor Números → ordenação textual (CA 74).
- Tipo de valor Data → ordenação por data convertida; valor não convertível → ordem original + log (CA 75, 76).
- Tipo de campo do formulário (caixa de seleção/marcador/listbox × demais × texto/área de texto) altera o valor gravado (CA 77, 78).
- Ambiente SQL Server ou Oracle (CA 98); sessão e permissão (CA 95, 96).

## Ambiguidades
- CA 76 "mantém a ordem original": (a) a lista inteira não é reordenada; (b) só o valor inválido fica na posição original e os demais são ordenados. O comentário de 27/10 adota (a) como hipótese.
- CA 73 "devolve nulo" para lista vazia: não esclarece se vale também para lista só com inativos (ver Informações ausentes).
- CA 78 "grava a descrição do valor... em campo de texto ou área de texto, concatena os valores": não deixa claro se a concatenação ocorre também em Seleção simples (um valor só) e se "outro tipo" inclui todos os demais tipos de campo.

## Riscos identificados
- Regressão na camada ECM: tipos ou valores inativos aparecendo no lançamento/busca, ou ordem errada, afetando usuários finais.
- Ordenação de Números como texto contraria a expectativa intuitiva ("10" antes de "9"); risco de ser reportada como defeito, apesar da decisão da PM de 22/10/2026.
- Falha na ordenação por data derrubar a requisição em vez de logar.
- Gravação de código ao invés de descrição (ou vice-versa) no Início com Publicação, corrompendo o formulário de processos.
- Divergência entre SQL Server e Oracle (chave gerada, paginação) e vazamento de detalhe técnico em erros.
- Comportamentos de borda (valor excluído/não numérico no Início com Publicação) sem definição, com risco de abortar o fluxo (comentário de 27/10 cita que hoje o código aborta, G-01).
