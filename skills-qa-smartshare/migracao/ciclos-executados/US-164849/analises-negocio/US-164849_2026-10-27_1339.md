# Análise de Negócio — #164849 Migração tela de gerenciamento | Gerenciamento de índice (BE) | Lançamento e integração

**Projeto:** SHARE-4 | **Tipo:** Product Backlog Item | **Status:** Committed

## Objetivo da alteração
A API (BE) deve gravar valor inicial, conexão, SQL de consulta e modo de comparação do índice com as regras do Clássico, e oferecer o serviço de Testar SQL, bloqueando qualquer comando que não seja SELECT. (descrição: User Story e Contexto)

## Comportamentos esperados (contratos verificáveis)
- Quando "Fixar índice na tela de lançamento" é salvo, o sistema deve persistir `st_fixo_lancamento` como 0 ou 1. (CA 31)
- Quando "Permitir edição durante o lançamento" está desligado, o sistema deve gravar `st_desabilita_lancamento = 1`; ligado grava 0; a leitura faz a conversão inversa. (CA 32)
- Quando Tipo de índice ≠ Seleção e Tipo de valor = Letras e Números, o sistema deve gravar o texto (até 50 caracteres) em `ds_valor_inicial_lancamento`. (CA 33)
- Quando Tipo de valor = Números, o sistema deve aceitar só dígitos (`\d+`) e rejeitar letras com "Somente números". (CA 34)
- Quando Informado + Data + "Outro", o sistema deve gravar a data em dd/mm/aaaa com hora zerada; data vazia é rejeitada com "Por favor, selecione uma data inicial.". (CA 35)
- Quando Informado + Data + "Data Atual", o sistema deve gravar `[DT_ATUAL]` e forçar `st_desabilita_lancamento = 1`; ao escolher "Outro" volta a "Desabilitado" = não. (CA 36)
- Quando Tipo de índice = Seleção, o valor inicial deve ser o `cd_indice` de valor cadastrado do mesmo tipo, ou vazio; código de outro tipo é rejeitado. (CA 37)
- Quando a inclusão de Seleção carrega o campo e o tipo ainda não tem código, a lista de valores iniciais deve vir vazia. (CA 38)
- Quando Tipo de índice = Específico ou Múltipla Seleção, o sistema deve ignorar o valor inicial, gravá-lo vazio e "Desabilitado" = não. (CA 39)
- Quando Informado + Tipo no DI = Consulta, sem conexão rejeita com "Por favor, preencha uma conexão."; sem SQL rejeita com "Por favor, preencha um comando SQL para consulta."; nada é gravado. (CA 40)
- Quando Tipo de índice ≠ Informado, o sistema deve gravar `cd_conexao` e `ds_sql` como NULL. (CA 41)
- Quando a lista de conexões é solicitada, o sistema deve retornar só conexões vinculadas (`PERFIL_CONEXAO`) aos perfis do usuário com permissão de leitura, sem duplicar, com primeiro item vazio. (CA 42)
- Quando o usuário grava o tipo apontando para conexão sem vínculo com seus perfis, o sistema deve rejeitar (validação também no servidor). (CA 43)
- Quando o SQL tem apóstrofos, o sistema deve gravar o texto íntegro (sem escape duplicado) e devolvê-lo idêntico na leitura. (CA 44)
- Quando Tipo de valor = Letras e Números com conexão, o sistema deve aceitar e gravar 0, 1 (Parcial/LIKE) ou 2 (Total/IGUAL); "Selecione" grava 0, não NULL. (CA 45)
- Quando não há conexão ou Tipo de valor ≠ Letras e Números, o modo deve ser gravado 0; na leitura, o campo só aparece se ≠ 0, Letras e Números e com conexão. (CA 46)
- Quando o teste de SQL é solicitado, o sistema deve executar o SQL na conexão escolhida e devolver campos e linhas paginadas; filtros entram com `AND` (se já há `WHERE`) ou `WHERE`, terminando em `1 = 1`. (CA 47)
- Quando o SQL tem tags `<campo id=... = códigoÍndice>`, cada tag deve ser trocada pelo valor já preenchido do índice indicado; sem valor, por vazio. (CA 48)
- Quando um filtro é aplicado, inteiro/decimal comparam por `=`; texto usa `=` só com modo Total (2) e `LIKE %v%` nos demais. (CA 49)
- Quando a conexão está indisponível ou o SQL é inválido, o sistema deve devolver erro de negócio legível, sem expor a string de conexão e sem travar a requisição (timeout). (CA 50)
- Quando o SQL tem INSERT, UPDATE, DELETE, DROP, ALTER, CREATE, TRUNCATE, MERGE, EXEC ou mais de um comando (`;`), o sistema deve rejeitar com "Somente comandos SELECT são aceitos.", sem gravar nem executar; aceita só instrução iniciada por SELECT (ignorando espaços, comentários e caixa), mantendo as tags do CA 48; vale mesmo sem validação do FE; índices antigos continuam abrindo, com erro ao salvar/testar. (CA 51)
- Quando qualquer operação é chamada sem sessão válida ou sem permissão no menu de Configurações, devolver 401/403 sem executar. (CA 95)
- Quando usuário sem permissão de gerenciar índices tenta incluir, alterar ou excluir, bloquear mesmo que veja a listagem. (CA 96)

## Regras explícitas
- Numeração dos critérios mantida da US única original, para rastreabilidade. (descrição: Origem)
- Modo de comparação idêntico ao Clássico: "Selecione" e fora de contexto gravam 0; 0, ausente e Parcial → LIKE; só Total (2) → IGUAL. (decisão PM 21/10/2026; CA 45, 46, 49)
- O BE bloqueia SQL que não seja SELECT ao salvar e ao testar; o Clássico não bloqueava. (decisão PM; CA 51)
- "Permitir edição" é invertido em relação a "Desabilitado"; "Data Atual" o desliga. (Figma 22/10/2026; CA 32, 36)
- Modo de comparação na inclusão lê do formulário de inclusão, sem replicar o bug do Clássico. (decisão 22/10/2026; CA 45)
- Valor inicial vazio padronizado em NULL, tratando leitura de NULL e de texto vazio. (decisão 22/10/2026; CA 33)
- Todo SQL usa parâmetros nomeados; nenhum texto do usuário é concatenado, exceto o SQL de consulta cadastrado. (CA 97)
- Comportamento idêntico em SQL Server e Oracle, inclusive chave gerada na inclusão e paginação. (CA 98)
- Erro técnico: mensagem padronizada ao FE, detalhe no log, sem vazar SQL, stack trace ou string de conexão. (CA 99)

## Regras implícitas
- IMPLÍCITA: o limite de 50 caracteres (CA 33) implica rejeição de texto maior, mas o critério não declara a mensagem — decorre do "até 50 caracteres".
- IMPLÍCITA: a validação de conexão por perfil (CA 43) e o bloqueio de SELECT (CA 51) devem ocorrer no servidor independentemente do FE, pois o CA 51 diz que vale "mesmo se o FE não validar" e o CA 43 diz que o BE "passa a validar também no servidor".
- IMPLÍCITA: com "Data Atual" (CA 36), a combinação "Permitir edição ligado + Data Atual" é inconsistente; o BE deve prevalecer com `st_desabilita_lancamento = 1` (o critério diz "força").
- IMPLÍCITA: a lista de conexões do CA 42 é usada também como base da validação do CA 43 (mesmo vínculo perfil × conexão).

## Condições e exceções
- Tipo de índice: Seleção, Informado, Específico, Múltipla Seleção determinam quais campos de lançamento/integração valem (CA 33, 36–41).
- Tipo de valor: Letras e Números, Números, Data determinam validação do valor inicial e do modo de comparação (CA 33–35, 45, 46).
- Presença de conexão condiciona o modo de comparação (CA 46).
- Perfis do usuário e permissão de leitura condicionam as conexões (CA 42, 43).
- Permissão de gerenciar índices distinta da permissão de visualização (CA 96).
- Índices antigos com SQL fora do padrão: abrem normalmente; o erro surge ao salvar/testar (CA 51).
- Banco SQL Server ou Oracle (CA 98).

## Ambiguidades
- CA 33 × CA 39: "diferente de Seleção" inclui Específico e Múltipla Seleção, que o CA 39 manda ignorar.
- CA 37, 39, 41 e a decisão de 22/10: valor "vazio" vs NULL. A decisão padroniza NULL, mas CA 37/39 dizem "vazio".
- CA 47: "terminando em `1 = 1`" admite duas leituras — filtros anexados após uma condição `1 = 1` inicial, ou `1 = 1` como cláusula final de fechamento.
- CA 51: "começa com SELECT" rejeita `WITH ... SELECT`; "mais de um comando (`;`)" pode ser lido como qualquer `;` ou só `;` fora de literal.
- CA 36: "ao escolher 'Outro' volta a 'Desabilitado' = não" — não está claro se é comportamento do BE ao gravar ou apenas do FE ao alternar.
- CA 46: "o modo volta para 0" (BE reescreve silenciosamente) vs rejeitar valor ≠ 0 enviado fora de contexto.
- CA 35: "grava a data em dd/mm/aaaa com hora zerada" — texto ou tipo data; formato de armazenamento não esclarecido.

## Riscos identificados
- CA 48 injeta valor de outros índices dentro do SQL, em tensão com o CA 97 (nenhum texto do usuário concatenado): risco de injeção por valor preenchido.
- Bloqueio de SELECT por lista de palavras/`;` pode gerar falso positivo (ex.: coluna `create_date`, `;` em literal) ou falso negativo (SELECT com efeito colateral).
- Índices antigos com SQL fora do padrão só falham ao salvar/testar; usuários podem estranhar o erro tardio (CA 51).
- Inversão `st_desabilita_lancamento` pode ser aplicada duas vezes ou esquecida na leitura (CA 32, 36).
- Gravar 0 (não NULL) no modo de comparação e NULL no valor inicial: leitura inconsistente (CA 33, 45, 46).
- Validação de conexão por perfil só no FE deixaria brecha (CA 43).
- Divergência de comportamento entre SQL Server e Oracle (paginação, chave gerada) (CA 98).
- Vazamento de string de conexão em erro de teste (CA 50, 99).
