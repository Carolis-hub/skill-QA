# Como trocar o banco do ambiente local (SQL Server para Oracle) em 4 passos

## Contexto

Os testes da US 160823 rodaram primeiro em Oracle, depois em SQL Server, e voltaram ao Oracle. A troca é manual em dois lugares (Share clássico e net8). Este registro guarda o procedimento que o dono do ambiente indicou e que foi executado e conferido em 06/11/2026 (direção SQL Server para Oracle).

## Aprendizado — procedimento (direção SQL Server para Oracle)

Pré-requisito: parar o Scheduler e o Worker BPM do net8 (e o serviço `SmartShareAgent`, se estiver rodando) antes de trocar.

1. **Share clássico:** abrir `http://localhost:58149/SmartShare/config/webconfig.aspx` e preencher:
   - Provider: `System.Data.OracleClient` (a lista dispara o desabilitar de "Base de Dados").
   - Servidor/Instância: `<host>:1521/SSHARE` (o host RDS está em `Variveis de Ambiente/variaveis-de-ambiente-smartshare.md`, seção Oracle).
   - Base de Dados: em branco (fica desabilitado no Oracle).
   - Usuário e senha: do schema Oracle (mesmo arquivo de variáveis; não copiar para outros documentos).
   - Caminho Virtual: `/smartshare/` (minúsculo, como indicado).
   - Usuário Administrador: `root` e a senha de teste do mesmo arquivo.
   - Clicar em **Salvar** (botão `btnSalvarAvancada`). Conferir a mensagem "Configurações Salvas com Sucesso!".
2. **O que o salvar já faz sozinho:**
   - Reescreve `SmartShare/SmartShareWeb/Web.config` (`ConnectionString`, `ProviderName`, `ConnectionStringCalendar`, `CaminhoSmartShare` e `CaminhoVirtualSmartShare`).
   - Reescreve o bloco `ConnectionStrings` de `smartshare-net8/src/3 - Core/Project.Core.Api/appsettings.json` (`DBType` = `Oracle`, `Schema` = schema Oracle, `DefaultConnection` criptografada). Foi confirmado por hash e diff.
3. **net8:** copiar o bloco `ConnectionStrings` completo do `appsettings.json` da API para o `appsettings.json` do Scheduler (`Project.Agent.WorkerScheduler`) e do Worker BPM (`Project.Agent.Worker.Bpm`), trocando só esse bloco (o resto do arquivo não muda).
4. **Subir os Workers:** eles leem o `appsettings.json` da pasta `bin\Debug\net8.0` (copiado no build). Sem rebuild, copiar o arquivo novo para a pasta `bin` de cada projeto antes de subir (ou compilar). Depois iniciar `SmartShareAgent_SchedulerWorker.exe` e `SmartShareAgent_BpmWorker.exe`.

## Como conferir que trocou (feito em 06/11/2026)

- Log do Worker BPM: "Iniciando worker/Bpm SHAREGUIZAO" (no SQL Server aparece `dbo`) e nenhum `ERROR` na partida.
- Tela de login do Share: "licenciado para ... - Oracle".
- `appsettings.json` dos três projetos com `DBType` igual e `DefaultConnection` idêntica.

## Pegadinhas observadas

- A primeira requisição ao Share depois do salvar leva de 30 a 40 s (recompilação e primeira conexão com o Oracle). Depois fica em ~0,3 s.
- A sessão do Share cai: é preciso entrar de novo (`root`).
- Cada banco tem os seus próprios valores de `JOB_CONFIG` Id 12 `Ativo` e do parâmetro 96 (nova API do Engine). Em 06/11/2026: Oracle com `Ativo=1` e parâmetro 96 = 0; SQL Server com `Ativo=0` e parâmetro 96 = 1. Conferir antes de testar.
- Parâmetro 96 = 1 só funciona com nginx roteando `/smartshare/api/` para a API (8081), ver o relatório 04 da US 160823.
- O Agent clássico (serviço `SmartShareAgent`) já tem os dois clientes (SQL Server e Oracle) no `ConfigClientes.xml` e não precisa dessa troca.
- Os `appsettings.json` e o `Web.config` aparecem como modificados no git: são alterações locais de ambiente, não de código. Não commitar.

## Direção inversa (Oracle para SQL Server) — informada pelo dono do ambiente, ainda NÃO executada por QA

O dono do ambiente informou em 06/11/2026 que a volta ao SQL Server funciona do mesmo modo: muda só o que se preenche na tela do passo 1. Os passos 2, 3 e 4 são os mesmos.

No `webconfig.aspx`:

- Provider: `System.Data.SqlClient` (opção da lista; o texto informado no chat tinha uma vírgula a menos, `System.DataSqlClient`).
- Servidor/Instância: `NOTE-74VQ\SQLEXPRESS`.
- Base de Dados: `ShareGuizao` (fica habilitada no SQL Server).
- Usuário: `guilherme.borges`; senha: a do SQL Server, no arquivo de variáveis (seção SQL Server).
- Caminho Virtual: `/SmartShare/` (com S e S maiúsculos; no Oracle é `/smartshare/`).
- Usuário Administrador: `root`; senha de teste do mesmo arquivo.
- Clicar em **Salvar** e conferir "Configurações Salvas com Sucesso!".

Depois: o salvar reescreve o `Web.config` do clássico e o bloco `ConnectionStrings` da API (`DBType` = `SQLServer`, `Schema` = `dbo`); copiar o bloco `ConnectionStrings` da API para o Scheduler e o Worker BPM, copiar o `appsettings.json` para a `bin` de cada um e subir os Workers. Conferir: log do Worker "Iniciando worker/Bpm dbo" e login do Share sem o texto "Oracle" na licença.

Valores que cada banco tinha ao fim dos testes de 06/11/2026: SQL Server com `JOB_CONFIG` Id 12 `Ativo=0` e parâmetro 96 = 1; Oracle com `Ativo=1` e parâmetro 96 = 0.

Pendente de confirmar na primeira vez que a troca for feita por QA: o resultado real (mensagem, log, tempo da primeira requisição). Atualizar esta entrada e mudar o título para refletir as duas direções.
